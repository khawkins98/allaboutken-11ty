# Architecture

How `allaboutken.com` is built. Source-of-truth files are listed alongside each section so you can read the real thing.

## Stack

| Layer           | Tool                                            |
| --------------- | ----------------------------------------------- |
| Site generator  | Eleventy v3 (`eleventy.js`)                     |
| Templates       | Nunjucks + Markdown (`src/site/`)               |
| Styles          | Sass, scoped to a CSS toggle                    |
| Keyword search  | Pagefind (Rust indexer, ~10 KB JS)              |
| Semantic search | Transformers.js + `Xenova/all-MiniLM-L6-v2`     |
| Hosting         | Vercel (auto-deploys from GitHub)               |
| CI              | GitHub Actions (`.github/workflows/`)           |

## Build pipeline

`yarn build` runs four steps in sequence (see `package.json` `scripts.build`):

1. **`yarn clean`** — `rm -rf build`. Fresh output every time.
2. **`yarn sass`** — Compile `src/components/vf-componenet-rollup/index.scss` → `build/css/styles.css`. No source map in production.
3. **`yarn eleventy`** — Run Eleventy with `ELEVENTY_ENV=production`:
   - Reads templates from `src/site/`
   - Applies collections, filters, shortcodes (see `eleventy.js`)
   - Runs the image transform plugin against generated HTML
   - Triggers Pagefind on the `eleventy.after` event to index the built site
4. **`yarn embeddings`** — `node scripts/generate-embeddings.mjs`. Walks `build/`, extracts text from pages tagged with `data-pagefind-body`, generates MiniLM-L6-v2 vectors, writes `build/semantic-search/vectors.json`.

`yarn dev` skips embeddings (too slow for hot reload) and runs `sass --watch` + `eleventy --serve` together via `concurrently`. Run `yarn build` once if you need `vectors.json` locally.

## Eleventy configuration

All configuration lives in `eleventy.js` (~430 lines). Notable areas:

- **Image transform** — `@11ty/eleventy-img`'s transform plugin rewrites `<img>` tags into responsive `<picture>` markup with `avif`, `webp`, `jpeg`, `gif` variants at widths `[320, 600, 900, 1280]`. A custom `filenameFormat` keeps filenames human-readable (`<dir-token>-<base>-<width>.<format>`) instead of the default hash. In dev, `transformOnRequest: true` defers processing.
- **Filters** — `dateDisplay`, `limitItems`, `ensureTrailingSlash`, `rssDate`, `rssLastUpdatedDate`, `emdash`, `htmlToAbsoluteUrls`, `sanitizeFeedHtml`, `wordCount`, `formatNumber`. Used in templates via `{{ value | filterName }}`.
- **Shortcodes** — `ogImageUrl` for OpenGraph image overrides.
- **Passthrough copy** — `.js` files, `src/site/images/`, favicon assets, `kh-font`, and raw `.html` are copied without transformation.
- **Collections** — `impactStories`, `blogPosts`, `allContent`.
- **Pagefind hook** — registers an `eleventy.after` hook that shells out to `pagefind --site build --exclude-selectors "pre, code"`. In `--serve` mode the child process is killed and restarted on each rebuild.

## Search architecture

Two independent systems, both static and run in the browser:

- **Pagefind** (keyword) — Built by the Eleventy post-build hook. Ships ~10 KB JS. Client fetches per-segment indexes on demand. UI lives in `src/site/search.njk`.
- **Semantic** (vector) — `scripts/generate-embeddings.mjs` writes `build/semantic-search/vectors.json` at build time. The browser loads `src/site/semantic-search.js`, which fetches the **same** model (`Xenova/all-MiniLM-L6-v2`) from HuggingFace via Transformers.js, embeds the query, and ranks vectors by cosine similarity. Model is ~23 MB and cached by Transformers.js via the Cache API.

> The model ID lives in **two** files and must match: `MODEL_NAME` in `scripts/generate-embeddings.mjs` and `MODEL_ID` in `src/site/semantic-search.js`.

## CSS toggle

All custom styles are nested under `body:has(#kh-css-toggle:checked)` (entry point: `src/components/vf-componenet-rollup/index.scss`). Unchecking the toggle leaves the site rendering with browser defaults only. Any new style added outside this scope will not apply when the toggle is on, and will apply even when the toggle is off — usually the wrong thing. See the in-site post on "CSS naked" for the rationale.

## Social cards

Auto-generated by Eleventy's screenshot service. Card pages live at `/social/<page-url>/`. Per-page override: `og_image: <full URL>` in frontmatter (note: `image` in frontmatter is the in-page hero, **not** the social card).

## Deployment

GitHub Actions (`.github/workflows/build-and-deploy.yml`) builds on every PR and pushes to `main`. The `deploy` job only runs on `refs/heads/main` and publishes to GitHub Pages. Vercel additionally auto-deploys from GitHub for the production site. See `docs/DEPLOYMENT.md` for redirect patterns and proxy details.
