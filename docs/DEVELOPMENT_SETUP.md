# Development setup

This guide covers local setup for developing `allaboutken-11ty`.

## Requirements

| Tool | Required version | Source of truth |
| --- | --- | --- |
| Node.js | `22` (recommended) | `.nvmrc`, CI workflow (`actions/setup-node@v6`) |
| Yarn | Yarn 1.x (`1.22.22` pinned via `packageManager`) | `package.json` |
| Git | Current stable | Local workflow + hooks |

`package.json` also declares `engines.node: >=20`, as required by the Eleventy 4 alpha, but local and CI are standardized on Node 22.

## Initial setup

```bash
nvm use
corepack enable
yarn install
```

`yarn install` runs the `prepare` script and configures the hooks in `.githooks/`, including commit-subject normalization and validation.
If your shell does not pick up the right Yarn automatically, `corepack` is the supported path here because `packageManager` pins Yarn 1.22.22.

## Daily development workflow

```bash
yarn dev
```

This runs:

1. Sass watch: compiles `src/components/vf-componenet-rollup/index.scss` to `build/css/styles.css`
2. Eleventy dev server: `ELEVENTY_ENV=development eleventy --serve --config=eleventy.js`

### Production-parity build

```bash
yarn build
```

This renders bootstrap HTML, generates embeddings and derived semantic data,
then renders the final Eleventy site.

## Recommended editor setup

The repo already includes `.vscode/settings.json` with Nunjucks spellcheck support:

```json
{
  "cSpell.enableFiletypes": ["nunjucks"]
}
```

Suggested additions in your local editor:

- Nunjucks syntax highlighting
- EditorConfig support
- Stylelint extension for SCSS/CSS
- A formatter/linter integration that respects the repo's `.githooks/commit-msg` subject rules

## Troubleshooting

### `nvm use` picks the wrong version

Ensure your shell has nvm loaded, then run:

```bash
nvm install 22
nvm use 22
```

### Styles look missing locally

This site supports CSS-off mode. In the page footer, verify the `CSS` checkbox is enabled.

### `yarn dev` works but semantic search is stale

Embeddings are not generated by `yarn dev`. Run:

```bash
yarn build
```

to refresh `build/semantic-search/vectors.json`.

### Service worker changes do not appear immediately

Service workers can continue serving cached responses until the updated worker takes control. After changing `src/site/sw.js` or registration in `src/site/scripts.js`:

```bash
yarn build
```

Then hard refresh the browser tab once so the latest worker is activated for that client session.

### Build feels slow on first full run

Expected: `@huggingface/transformers` and ONNX runtime assets make first-time setup heavy.
